# Baliset test VM

A headless QEMU/KVM guest that runs Tony's desktop from `~/dotfiles`: the same niri
build and `config.kdl`, the stillsuit shell with its tray and audio/media panel, and
home-manager's desktop modules. Use it to launch Baliset, screenshot it, and click and
type into it from a shell with no display.

Everything runs from this directory. State (disk image, throwaway SSH key, QMP socket,
logs) lives in `.state/`, which git ignores.

## Scripts

| Command | What it does |
|---|---|
| `vm/up [--keep-disk] [--timeout S]` | Builds the VM, boots it in the background, and returns once niri is up and the stillsuit bar is mapped. The disk starts fresh each time unless you pass `--keep-disk`. |
| `vm/down` | Quits QEMU and its virtiofsd helpers. |
| `vm/run CMD...` | Runs a command in kabilan's graphical session. Its output and exit code come back to you. |
| `vm/spawn [-E VAR=VAL]... NAME CMD...` | Starts a long-running app as the transient user unit `vm-NAME`, so it outlives the call. |
| `vm/shot OUT.png` | Saves the whole 1920x1080 screen through a QMP screendump. |
| `vm/click [--right\|--middle] [--double] X Y` | Moves the USB tablet to a pixel and clicks. |
| `vm/move X Y` | Moves the pointer without clicking (hover, tooltips). |
| `vm/scroll X Y up\|down [STEPS]` | Turns the scroll wheel at a pixel. |
| `vm/key COMBO...` | Sends key combos made of QEMU qcodes joined by `-`, e.g. `ret`, `esc`, `ctrl-c`, `super-a`, `alt-f4`. `super` (or `mod`) is niri's Mod key. |
| `vm/type TEXT` | Types ASCII text on a US layout. |

`vm/run` and `vm/spawn` go over SSH. The key is generated by `vm/up`, reaches the guest
as a systemd credential, and the port is forwarded on 127.0.0.1 only. If your shell's
cwd is inside the project, the command runs in the same directory in the guest.
Otherwise it runs in `/home/kabilan`.

Pointer and keyboard events go through QMP to QEMU's USB tablet and virtio keyboard.
niri sees them as real input devices, so focus, hover and keybindings behave as they
do on the desktop.

```sh
vm/up
vm/spawn tone mpv --no-video --force-media-title="Test" 'av://lavfi:sine=frequency=440'
vm/key super-a                     # stillsuit audio panel, with the media widget
vm/shot /tmp/audio.png
vm/run playerctl status
vm/run journalctl --user -u vm-tone
vm/run systemctl --user stop vm-tone
vm/down
```

Logs inside the guest: `vm/run journalctl --user -u niri`,
`vm/run journalctl --user -u stillsuit-shell`. The serial console is in
`.state/console.log`.

## Running a host-built Baliset

The guest mounts the host's `/nix/store` and this project, read-only, at the same
paths. A binary built on the host runs by path. A `cargo build` binary dlopens its
Wayland, Vulkan and ALSA libraries, though, and its RPATH covers only libxkbcommon, so
pass the dev shell's `LD_LIBRARY_PATH`:

```sh
nix develop -c cargo build
vm/spawn -E "LD_LIBRARY_PATH=$(nix develop -c printenv LD_LIBRARY_PATH)" \
  baliset target/debug/baliset --demo
```

If you don't, winit panics with "The wayland library could not be loaded". A `nix
build` result has these libraries wrapped in, so it needs nothing extra. Vulkan needs
no extra variables: the session sets `VK_DRIVER_FILES` to Mesa lavapipe, the only
device in the guest.

## What matches the real desktop

The VM reads the dotfiles' working tree through `git+file:///home/kabilan/dotfiles`,
so dotfiles edits are picked up on the next `vm/up`. It reuses:

- the dotfiles' `flake.lock`: same nixpkgs, home-manager, niri-flake and stylix, plus
  the same overlay list as `makeSystem`, so most packages come straight out of the host
  store;
- NixOS modules `modules/nixos/wayland/niri.nix` (niri-unstable at the dotfiles' pin),
  `desktop-wayland.nix`, `theme.nix` with stylix, and the niri-flake module;
- home-manager modules `home/desktop/wayland` (niri, quickshell/stillsuit, swaylock),
  `modules/home/stillsuit`, `fonts.nix`, `gtk.nix`, `stylix.nix` and `ghostty.nix`;
- `config.kdl` itself, linked out of the dotfiles source through `~/dotfiles`, with
  all its window rules and binds. Stillsuit's plugin roots resolve the same way.

## What differs

- **niri is patched.** Its tty backend refuses software EGL renderers (llvmpipe) and
  has no setting to allow them. The VM builds the same niri revision with that check
  removed and a fallback to the card's render node (`guest.nix`). The first build of it
  takes about 8 minutes, and later boots reuse it.
- **`host.kdl`** is VM-specific: one `Virtual-1` output at 1920x1080, scale 1, the same
  wallpaper as sietch. The
  sietch-only `debug { disable-pipewire-dmabuf }` is dropped.
- **Login:** greetd starts `niri-session` as kabilan with no prompt. The real machine
  logs in on tty1 and starts niri by hand. Both end in the same systemd user session.
- **Left out:** NVIDIA, agenix and all secrets, backups, deploy, tailscale and VPNs,
  self-hosted services, docker, syncthing, keyd, bluetooth, gnome-keyring, the brotli
  CVE graft, `home/services` (timers and agents), and the app list in
  `home/default.nix`. As a result, `spawn-at-startup "obsidian"` and the dictation and
  dev-checkouts integrations have nothing to start. `nirius` is installed so `niriusd`
  runs.
- **Audio:** PipeWire with a null sink named "VM Null Output", the default for Pulse and
  ALSA. There is no sound card.
- **Graphics:** virtio-gpu without 3D. niri and GL clients render with llvmpipe, and
  Vulkan clients use lavapipe.
- **Extras in the guest:** `vm-session-exec` (used by `vm/run`), `vm-tray-standin`
  (pasystray, a StatusNotifierItem app), mpv with its MPRIS script, playerctl, foot,
  vulkan-tools, mesa-demos, grim and wtype.

## Notes

- Tray icons given by theme name (`IconName`, e.g. pasystray's `audio-volume-high`)
  draw as Qt's missing-icon checkerboard, because stillsuit's Qt has no icon theme set.
  The host's session environment has the same setup, so this is probably true on the
  real desktop as well. Baliset's pixmap icon draws correctly.
- Left-clicking a tray item makes stillsuit call `org.kde.StatusNotifierItem.Activate`.
  Right-clicking opens the item's DBusMenu in a stillsuit panel.
- Resources: 8 vCPUs, 8 GiB RAM, an 8 GiB qcow2 disk, user-mode networking. Change
  them in `guest.nix`.
